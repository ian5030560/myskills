# 03: 裁切腳本（剝邊規則）

**What to build:** AI 指定一張頁面圖和一個寬鬆的比例範圍，腳本從範圍邊緣往內剝除圖說、內文、章節標題、頁首頁尾、隔壁圖的細條與白邊，從 PDF 以 200 dpi、不含格線重新渲染出**裁切圖**，並印出實際使用的範圍。規格與各條門檻見 spec 的「Crop script」與「Crop trimming rules」（來自原型）。

**Blocked by:** 02（需要頁面圖的檔名規則與 manifest）

**Status:** done (uncommitted)

- [x] 輸入：頁面圖路徑、`x0,y0,x1,y1`（0–1 頁面比例）、名稱；頁碼取自檔名，PDF 取自 manifest
- [x] 輸出 `images/<name>.png`，200 dpi、無格線
- [x] stdout 印出最終範圍（頁面比例）
- [x] 只往內收、不切進非下列類型的內容：圖說（`Figure N`/`Fig. N`/`Table N` 開頭）、章節標題、內文段落、頁首頁尾
- [x] 內文段落判定：主要字級與全文最常見字級差 ≤0.6pt、至少一行 ≥60 字、寬度 ≥35% 頁寬（純文字條列組成的圖、字較小的表格不被剝）
- [x] 左右邊緣：跨邊且在範圍內不到一半寬度的內文段落，把該側收到段落外
- [x] 上下邊緣反覆剝除最外側的上述文字區塊；只計入與範圍垂直重疊 ≥4pt 的圖形
- [x] 去白邊時，丟掉上下邊緣與主體間隔 ≥6pt、高度 <5pt 的細條；保留 2pt 邊距
- [x] 剝到空或幾乎空時以非零狀態結束並說明需要重框
- [x] 命令列測試（以印出的最終範圍驗證，不做影像分析）：圖形＋下方圖說＋內文＋頁首、寬鬆範圍 → 範圍排除圖說／內文／頁首且完整包住圖形；同頁上下兩張圖；純文字條列圖不被剝；跨側邊內文被切；剝到空回傳錯誤；輸出圖尺寸符合 200 dpi
- [x] pylint 通過

## Comments

- 實作：`crop_figure.py --page-image pages/pN.png --box x0,y0,x1,y1 --name <name>`，輸出 `images/<name>.png`（200 dpi、無格線），stdout 印 `image:` 與 `box:`（頁面比例，小數三位）。命令列測試 15 個（`test_crop_figure.py`），測試 PDF 在 `conftest.py` 產生後用 `render_pages.py` 渲染。整套 `tests/write_paper_notes/` 70 個通過，三個新腳本一起跑 pylint 10/10。
- 與 spec 的差異：
  - 內文段落門檻放寬為「至少一行 ≥40 字、寬度 ≥30% 頁寬」（spec 為 60 字、35%）。雙欄論文一欄的行寬約 45–55 字、欄寬約 35% 頁寬，原門檻會讓跨側邊的內文判斷失效；字級必須等於全文主要字級這條仍是保護圖內文字與小字表格的主要條件。
  - 腳本不是完全獨立：頁首頁尾判定直接沿用 `extract_text.py` 的函式（01 的 Comments 提到的放寬規則），`render_pages.py` 也改用 `extract_text.py` 的共用命令列解析，避免 pylint duplicate-code 與規則分歧。
- 錯誤處理：範圍格式錯誤、頁面圖不存在或檔名不是 pN.png、缺 `source.json`、manifest 指向的 PDF 不存在、頁碼超出範圍、剝完沒有內容，都以狀態 1 結束並說明原因。`--name` 帶 `.png` 不會重複副檔名。
- 實測：把先前五個模型試裁的 15 個範圍在 cs.pdf、survey.pdf 上重跑，結果與原型一致；只框到內文的範圍正確回報錯誤。cs.pdf Figure 2 底部下標貼齊邊緣（圖說區塊上緣和下標很接近），內容沒有遺失。
