# 04: evaluate-paper 核心流程：給一篇 PDF 得到判讀報告

**What to build:** 使用者給 AI 一篇論文 PDF 與自己的研究問題，得到一份「結論在前」的判讀報告：文章身分卡、用腳本查到的外部指標、內容判斷、用途標記與「仍需確認」。報告先寫到暫存區、自我檢查後完整顯示，使用者同意才複製到正式位置。這一步還沒有標準檢查表，研究設計相關的判斷先註明「待檢查表」。規格見 `.scratch/evaluate-paper/spec.md` 的 Implementation Decisions「evaluate-paper skill 的組成」「判讀流程」「報告格式與儲存」；詞彙見 `GLOSSARY.md` 的「判讀」；決定見 `docs/adr/0002-appraisal-three-stages-no-score.md`。投影片的判讀依據見 `.scratch/evaluate-paper/research/`。

- [x] 內容判斷規則檔（依投影片整理）：來源能否核對、是否回答研究問題、說法是否被證據支持、測量是否合適、推論範圍與單位是否合適；論文含 AI 摘要時加做摘要忠實度檢查；研究設計嚴謹度不屬於此階段；每個判斷附原文位置，資訊不足要明寫
- [x] 結論：用途標記（主報告／背景／比較／暫不使用）相對於使用者的研究問題，附理由與「仍需確認」；不打分數或等級

- [x] 儲存與顯示：先寫到暫存區（環境有專用暫存資料夾就用它，否則系統暫存資料夾）的 `evaluate-paper/<pdf-stem>/appraisal.md`，同名覆蓋；自我檢查（對照規則檔，修到全部通過）後完整顯示；最後一行列出暫存檔路徑並詢問是否存到 `<output-dir>/<pdf-stem>/appraisal.md`，同意就複製、不重新產生；一開始就要求存檔或指定輸出位置時判讀完直接複製
