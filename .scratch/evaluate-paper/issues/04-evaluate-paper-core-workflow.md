# 04: evaluate-paper 核心流程：給一篇 PDF 得到判讀報告

**What to build:** 使用者給 AI 一篇論文 PDF 與自己的研究問題，得到一份「結論在前」的判讀報告：文章身分卡、用腳本查到的外部指標、內容判斷、用途標記與「仍需確認」。報告先寫到暫存區、自我檢查後完整顯示，使用者同意才複製到正式位置。這一步還沒有標準檢查表，研究設計相關的判斷先註明「待檢查表」。規格見 `.scratch/evaluate-paper/spec.md` 的 Implementation Decisions「evaluate-paper skill 的組成」「判讀流程」「報告格式與儲存」；詞彙見 `GLOSSARY.md` 的「判讀」；決定見 `docs/adr/0002-appraisal-three-stages-no-score.md`。投影片的判讀依據見 `.scratch/evaluate-paper/research/`。

**Blocked by:** 01、03

**Status:** ready-for-agent

- [ ] 新增 `evaluate-paper` skill：`SKILL.md` 少於 500 行，frontmatter 只用規格允許的欄位，`compatibility` 寫明需要網路、不需要金鑰、有相關 MCP 時可多查到哪些指標；版本放 `metadata.version`；`references/` 的檔案都由 `SKILL.md` 直接引用
- [ ] 研究問題：使用者有給就用；沒給時 AI 推斷「使用者的研究問題」（不是論文自己的研究問題）並請使用者確認後再往下做
- [ ] 文章身分卡：書目與 DOI、發表來源、文章類型、所讀版本、審查狀態，只辨識不判斷；預印本或未審查版本明確標示
- [ ] 外部評估：說明如何執行指標腳本並解讀輸出（撤稿規則、「查無撤稿紀錄」的措辭、來源失敗逐一說明）；指標只當輔助線索，撤稿是唯一可改變結論的指標
- [ ] 內容判斷規則檔（依投影片整理）：來源能否核對、是否回答研究問題、說法是否被證據支持、測量是否合適、推論範圍與單位是否合適；論文含 AI 摘要時加做摘要忠實度檢查；研究設計嚴謹度不屬於此階段；每個判斷附原文位置，資訊不足要明寫
- [ ] 結論：用途標記（主報告／背景／比較／暫不使用）相對於使用者的研究問題，附理由與「仍需確認」；不打分數或等級
- [ ] 報告格式規則檔：結論在前，其次身分卡、外部評估、內容判斷；每個指標附來源、識別碼與查詢日期；報告語言跟隨使用者，語言不明時詢問
- [ ] 儲存與顯示：先寫到暫存區（環境有專用暫存資料夾就用它，否則系統暫存資料夾）的 `evaluate-paper/<pdf-stem>/appraisal.md`，同名覆蓋；自我檢查（對照規則檔，修到全部通過）後完整顯示；最後一行列出暫存檔路徑並詢問是否存到 `<output-dir>/<pdf-stem>/appraisal.md`，同意就複製、不重新產生；一開始就要求存檔或指定輸出位置時判讀完直接複製
- [ ] 指標快取：腳本輸出由 AI 存成同一暫存資料夾的 `metrics.json`；同一篇論文同一天重跑時沿用，報告記錄原始查詢日期
- [ ] 與 `write-paper-notes` 互相獨立，不共用程式
- [ ] 全 repo 的 skill 規格測試通過；lint 指令涵蓋該 skill 的腳本
- [ ] 對一篇真實論文（`test-papers/` 內，文件中只用代稱）跑一次，確認能產出符合格式的報告，並把觀察記錄在本 ticket 的 Comments
